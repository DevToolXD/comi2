# 토스(Toss) UI · 인터페이스 스타일 가이드

> 한국 금융 슈퍼앱 **토스(Toss, 운영사 비바리퍼블리카)** 의 시각 스타일(UI)과 인터페이스·경험 방식(UX)을 한 문서에 정리했어요.
> 토스처럼 보이고 토스처럼 동작하는 화면을 만들 때 참고할 수 있도록 원칙과 실제 수치를 함께 적었어요.

### 이 문서를 읽는 법

값마다 출처를 표시했어요. 믿을 수 있는 정도가 서로 다르기 때문이에요.

| 표시 | 의미 |
| --- | --- |
| **[TDS]** | 토스가 npm에 공개한 공식 디자인 시스템 패키지(`@toss/tds-colors@0.1.0`, `@toss/tds-mobile@2.5.1`)에서 직접 확인한 값 |
| **[공식]** | 토스가 직접 발표한 자료(toss.tech, 토스피드, Simplicity 컨퍼런스, 앱인토스 개발자센터) |
| **[관찰]** | 토스 앱을 보고 정리한 패턴. 공식 규칙은 아니에요 |

기준 시점은 2026년 9월이에요. TDS는 계속 바뀌므로, 실제로 구현할 때는 [앱인토스 개발자센터](https://developers-apps-in-toss.toss.im/)의 최신 문서를 함께 확인하세요.

## 1. 디자인 철학과 제품 원칙

### 1.1 토스는 어떤 회사인가

- 2015년 **간편송금**으로 시작한 한국의 핀테크 회사예요. 운영사는 비바리퍼블리카예요.
- 지금은 송금, 결제, 자산 조회, 대출, 보험, 증권(토스증권), 은행(토스뱅크)까지 하나의 앱에 담은 **금융 슈퍼앱**이에요.
- "공인인증서, 보안카드, 복잡한 입력" 같은 한국 금융 앱의 불편함을 없애는 것에서 출발했어요. 그래서 디자인 목표도 **어렵고 무서운 금융을 쉽고 편하게** 만드는 거예요.
- 매년 디자인 컨퍼런스 **Simplicity**를 열어 디자인 과정과 원칙을 공개해요. [공식]

### 1.2 핵심 가치: Simplicity

토스 제품 원칙에서 **한 번도 바뀐 적 없는 핵심 가치는 단순함(Simplicity)** 이에요. 토스가 말하는 단순함은 이런 상태예요. [공식]

> 사용자가 서비스를 쓰기 위해 **따로 알아야 할 것도, 배워야 할 것도 없이 바로 이해할 수 있는 상태**

"미니멀한 스타일"을 말하는 게 아니에요. **사용자의 생각하는 부담을 줄이는 것**이 목표예요. 화면이 깔끔해 보이는 건 그 결과일 뿐이에요.

### 1.3 제품 원칙 (Product Principles, PP)

토스는 제품을 만드는 원칙을 **Product Principle(PP)** 이라 부르고, 좋은 제품과 나쁜 제품을 가르는 기준으로 써요. 공개된 주요 원칙은 다음과 같아요. [공식]

| 원칙 | 뜻 | UI에서 어떻게 나타나는가 |
| --- | --- | --- |
| **One Thing for One Page** | 한 화면은 하나의 메시지만 전달해요. 불필요한 요소는 지우고, 빼고, 없애요. | 입력 화면마다 질문이 하나예요. 큰 제목 하나와 입력 칸 하나, 버튼 하나로 구성해요. |
| **Easy to Answer** | 사용자가 만나는 모든 질문은 **3초 안에 답할 수 있어야** 해요. 기억하기 어려운 정보는 자동으로 채워요. | 계좌번호 대신 "최근 보낸 사람" 목록을 보여줘요. 은행 선택은 로고 그리드로, 날짜는 휠로 골라요. |
| **Value First, Cost Later** | 제품의 가치를 먼저 전달하고, 정보 입력 같은 **비용은 나중에** 요구해요. | 혜택과 결과(예: "받을 수 있는 환급금 ○○원")를 먼저 보여주고, 본인인증과 약관 동의는 뒤로 미뤄요. |
| **Casual Concept** | 전문 금융 용어나 개념을 이해하는 수고를 사용자에게 넘기지 않아요. 친숙한 개념으로 바꿔 전달해요. | "만기 일시 상환" 대신 "끝날 때 한 번에 갚기"처럼 풀어서 써요. |
| **Minimum Features** | 이 기능 없이는 **절대로** 목표를 이룰 수 없는지 다시 생각해요. 기능이 늘수록 제품은 어려워지고 개선도 느려져요. | 옵션과 설정을 최소화하고 좋은 기본값을 줘요. 고급 기능은 숨겨요. |

> 참고로, 토스 추천 화면 관련 글에서는 "추천할 때는 **제일 좋은 것 하나**면 된다"는 관점도 소개했어요. 선택지를 늘어놓기보다 최선의 하나를 제시하는 거예요. [공식]

### 1.4 원칙이 만드는 시각적 결과 [관찰]

위 원칙을 따르면 화면은 자연스럽게 이런 모습이 돼요.

- **여백이 많아요.** 한 화면에 정보가 적으니 남는 공간이 넓어요.
- **글씨가 커요.** 메시지가 하나라서 크게 보여줄 수 있어요.
- **색이 적어요.** 강조할 것이 하나라서 강조색도 하나면 돼요.
- **장식이 없어요.** 테두리, 그림자, 그라디언트 같은 장식 요소를 거의 쓰지 않아요.
- **화면 수는 많아요.** 한 화면에 하나씩 묻기 때문에 단계는 늘어나요. 대신 각 단계가 매우 빨라요.

## 2. 컬러 시스템

### 2.1 운용 원칙 [관찰]/[TDS]

1. **무채색이 90% 이상이에요.** 배경은 흰색, 글자는 그레이 계열이에요.
2. **강조색은 Blue 500 하나예요.** 주요 버튼, 링크, 선택 상태, 입력 커서(caret)에 써요. [TDS]
3. **그레이에 푸른 기가 있어요.** `#191F28`, `#4E5968`처럼 약간 푸르스름한 쿨 그레이라서 차갑지만 깨끗하고 신뢰감 있어 보여요. 투명 그레이(`greyOpacity`)도 순수 검정이 아니라 남색(`rgb(0,27,55)` 근처)을 바탕으로 만들어요. [TDS]
4. **의미색은 기능이 있을 때만 써요.** 빨강은 오류·위험·주의, 초록은 성공·완료, 주황과 노랑은 경고·알림에 써요.
5. **금융 데이터 색은 한국 관례를 따라요.** 주가나 수익률이 **오르면 빨강, 내리면 파랑**이에요. 미국식(상승=초록)과 반대예요. [관찰]
6. **일러스트와 카테고리 구분**에는 teal, purple 등 보조 팔레트를 써요.

## 3. 타이포그래피

### 3.1 서체

**Toss Product Sans (토스 프로덕트 산스)** [공식]

- 토스 앱을 위한 **전용 서체**예요. 2020년 여름 **산돌**과 함께 시작해 7개월 동안 14번 협의한 끝에 첫 버전이 나왔어요. 두 번째 버전부터는 **이도타입**과 함께 필드 테스트를 거치며 개선하고 있어요.
- **한글**: 원래 쓰던 *Sandoll 고딕Neo1*을 거의 그대로 유지했어요.
- **숫자와 라틴 문자, 문장부호**: 한글에 맞춰 **새로 설계**했어요. 금융 서비스에서는 숫자와 기호가 가장 중요하기 때문이에요.
  - 숫자와 영문은 한글보다 **약간 두껍게** 만들어 섞어 써도 무게가 고르게 보여요.
  - `%` `,` `+` `-` `→` 같은 기호는 UI 요소처럼 쓰이기 때문에 **크기와 여백을 따로 조정**하고, 가운데 정렬과 같은 두께로 보이도록 다듬었어요.
- **3가지 구성**: 범용 구성 / 토스 앱에 맞게 일부 문장부호 모양을 바꾼 구성 / 웹용 경량 구성.
- 토스 외부 프로젝트에서는 쓸 수 없는 전용 서체예요. 비슷한 느낌이 필요하면 **Pretendard** 같은 공개 한글 고딕을 쓰는 경우가 많아요. [관찰]

```css
font-family: "Toss Product Sans", -apple-system, BlinkMacSystemFont,
  "Apple SD Gothic Neo", Pretendard, "Noto Sans KR", sans-serif;
```

### 3.2 타입 스케일 [TDS]

TDS는 **기본 7단계(`t1`~`t7`)** 와 그 사이를 채우는 **보조 13단계(`st1`~`st13`)** 로 모두 20단계예요. 11px부터 30px까지 1px 간격으로 전부 들어 있어요.

**기본 스케일 (먼저 쓰는 것)**

| 토큰 | 크기 | 줄 높이 | 비율 | 대표 용도 [관찰] |
| --- | --- | --- | --- | --- |
| `t1` | **30px** | 40px | 1.33 | 큰 금액, 히어로 숫자, 큰 입력 칸 |
| `t2` | **26px** | 35px | 1.35 | 화면 대제목 |
| `t3` | **22px** | 31px | 1.41 | 화면 제목, 질문형 헤드라인 |
| `t4` | **20px** | 29px | 1.45 | 섹션 제목, 다이얼로그 제목(기본값 [TDS]) |
| `t5` | **17px** | 25.5px | 1.5 | **본문 기본**, 목록 제목, 버튼 글자 |
| `t6` | **15px** | 22.5px | 1.5 | 보조 본문, 부제, 작은 버튼 |
| `t7` | **13px** | 19.5px | 1.5 | 캡션, 날짜, 뱃지 옆 텍스트 |

**보조 스케일 (필요할 때만)**

| 토큰 | 크기 / 줄 높이 | 토큰 | 크기 / 줄 높이 |
| --- | --- | --- | --- |
| `st1` | 29 / 38px | `st8` | 19 / 28px |
| `st2` | 28 / 37px | `st9` | 18 / 27px |
| `st3` | 27 / 36px | `st10` | 16 / 24px |
| `st4` | 25 / 34px | `st11` | 14 / 21px |
| `st5` | 24 / 33px | `st12` | 12 / 18px |
| `st6` | 23 / 32px | `st13` | 11 / 16.5px |
| `st7` | 21 / 30px | | |

**줄 높이 규칙**

- **17px 이하는 1.5배**로 여유 있게 잡아요.
- 글자가 커질수록 비율을 줄여 30px에서는 **약 1.33배**까지 조여요. 큰 제목이 붕 떠 보이지 않게 하기 위해서예요.
- 컴포넌트 내부에서는 별도의 줄 높이 토큰도 써요. [TDS]
  - `line-height-xs` = **1.252** (입력 칸 한 줄)
  - `line-height-s` = **1.35** (목록 텍스트)
  - `line-height-m` = **1.5** (문단)

### 3.3 굵기 [TDS]/[관찰]

TDS가 쓰는 굵기는 **4단계**예요: `regular`(400), `medium`(500), `semibold`(600), `bold`(700).

| 굵기 | 쓰는 곳 |
| --- | --- |
| **Bold (700)** | 화면 제목, 섹션 제목, 금액, 작은 섹션 머리말 |
| **Semibold (600)** | **모든 버튼 글자**([TDS] 버튼 `fontWeight: 600`), 토스트, 강조 라벨 |
| **Medium (500)** | 목록 항목, 선택지, 부제 |
| **Regular (400)** | 설명문, 캡션, 푸터 |

### 3.5 숫자와 금액 표기 [관찰]

금융 앱이라서 숫자 표기가 스타일의 중심이에요.

- **세 자리마다 쉼표**: `1,250,000원`
- **단위는 숫자 바로 뒤에 붙여요**: `12,000원`, `3.5%`
- **금액은 가장 크고 굵게** (`t1`~`t2`, bold, `grey900`), 설명은 작게 (`t6`~`t7`, `grey600`).
- **증감은 부호와 색을 함께** 표시해요: `+12,300원 (+2.4%)`는 빨강, `-5,000원 (-1.1%)`은 파랑. 색을 구분하기 어려운 사용자를 위해 부호를 꼭 붙여요.
- 큰 금액은 상황에 따라 `1억 2,500만원`처럼 **한글 단위**로 줄여서 읽기 쉽게 해요.
- 숫자가 바뀔 때는 자릿수가 굴러가듯 바뀌는 **숫자 롤링 애니메이션**을 써요. ([8.4](#84-토스다운-모션-연출-관찰공식) 참고)

### 3.6 글자 크기 확대 대응 (Dynamic Type) [TDS]

TDS는 OS의 글자 크기 설정을 따라가되, **큰 글자는 덜 커지고 작은 글자는 더 커지도록** 압축해서 키워요. 화면이 깨지지 않으면서 작은 글씨의 가독성을 확보하는 방식이에요.

**iOS 글자 크기 단계와 배율**

| 단계 | Large | xLarge | xxLarge | xxxLarge | A11y M | A11y L | A11y xL | A11y xxL | A11y xxxL |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 배율 | 100% | 110% | 120% | 135% | 160% | 190% | 235% | 275% | 310% |
| `t1` (30px) → | 30 | 32 | 34 | 36 | 40 | 41 | 41 | 42 | **42** |
| `t5` (17px) → | 17 | 19 | 21 | 23 | 27 | 32 | 36 | 38 | **39** |
| `t7` (13px) → | 13 | 15 | 17 | 19 | 21 | 24 | 27 | 30 | **34** |

- 30px 제목은 최대 42px(1.4배)까지만 커지지만, 13px 캡션은 34px(2.6배)까지 커져요.
- Android도 배율을 곱한 뒤 토큰별 **최대값(30px→42, 17px→39, 13px→34, 11px→31)** 으로 제한해요.
- 너무 커지면 레이아웃이 깨지는 곳에는 `FontScaleLimit`로 확대 한도를 따로 걸어요. 예를 들어 문단 목록은 160%까지만 커져요.

## 4. 레이아웃과 간격

### 4.1 기본 격자 [TDS]/[관찰]

토스는 기본적으로 **모바일 단일 칼럼**이에요. PC 웹에서도 모바일 폭의 칼럼을 가운데 두고 바깥은 `#F6F7F9`로 채워요.

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 화면 좌우 여백(콘텐츠) | **24px** | [TDS] 상단 제목, 목록 행 왼쪽, line형 입력 칸 |
| 하단 버튼 영역 좌우·하단 여백 | **20px** | [TDS] BottomCTA `padding: 0 20px 20px` |
| box형 입력 칸 좌우 | **20px** | [TDS] |
| 목록 행 오른쪽 여백 | **16px** | [TDS] ListRow `16px 16px 16px 24px` |
| 구분선 들여쓰기 | 왼쪽 **24px** | [TDS] Border `padding24` |

### 4.2 화면 골격 [관찰]

```
┌──────────────────────────────┐
│ ←                        ⋯  │  상단 내비게이션: 뒤로 가기 + (선택) 오른쪽 버튼
│                              │  ↕ 24px (upperGap)
│ 얼마를 보낼까요?             │  제목 t3~t2 bold grey900, 좌 24px
│ 내 토스뱅크 통장에서 출금돼요  │  부제 t6 grey600
│                              │  ↕ 24px (lowerGap)
│ ──────────────────────────── │
│  [ 입력 / 목록 / 콘텐츠 ]      │
│                              │
│                              │  ← 넉넉한 빈 공간
│                              │
│ ░░░░░░░░ 그라디언트 ░░░░░░░░ │  버튼 위 콘텐츠를 흰색으로 부드럽게 가림
│ ┌──────────────────────────┐ │
│ │           다음            │ │  주요 버튼 56px, 좌우·하단 20px
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

**상단 제목 영역(Top) 규격 [TDS]**

- 위아래 여백 기본 **24px**(`upperGap`, `lowerGap`), 왼쪽 **24px**
- 제목 위 요소(upper)와의 간격 **16px**, 아래 요소(lower)와의 간격 **16px**
- 부제는 제목 아래 **4px**
- 오른쪽에 버튼을 둘 수 있어요(medium 크기).

### 4.3 수직 리듬 [관찰]

- 화면 = **제목 블록 → 콘텐츠 블록 → 하단 고정 버튼**의 3단 구조가 기본이에요.
- 서로 다른 성격의 섹션은 **16px 회색 띠**로 크게 나누고, 같은 섹션 안의 항목은 **들여쓴 1px 선** 또는 여백만으로 나눠요.
- 카드를 줄줄이 쌓기보다는 **흰 배경 위의 목록**을 기본으로 써요. 홈 화면처럼 여러 서비스를 모아 보여줄 때만 회색 배경 위 흰 카드를 써요.

## 5. 형태: 모서리, 그림자, 구분선

### 5.1 모서리 둥글기 [TDS]

토스는 **크게 둥근 모서리**가 특징이에요. 요소가 클수록 더 둥글어요.

| 요소 | 둥글기 |
| --- | --- |
| 버튼 small (32px) | **8px** |
| 버튼 medium (38px) | **10px** |
| 버튼 large (48px) | **14px** |
| 버튼 xlarge (56px) | **16px** |
| 목록 행 눌림 하이라이트 | **12px** |
| box형 입력 칸 | **14px** |
| 선택 카드(체크박스 카드), 말풍선(Bubble) | **16px** |
| 툴팁 small / medium | 12px / 16px |
| 스위치 트랙 | **15px** (50×30px 알약형) |
| 다이얼로그, 용어 설명 팝업(WikiText) | **24px** |
| 바텀시트 (화면 양옆 10px 띄운 카드형) | **28px** |
| 토스트 | 한 줄이면 **알약형(100px)**, 여러 줄이면 **20px** |

| 하단 전체 너비 버튼(`display="full"`) | **0px** (화면 끝에 붙는 형태) |

### 5.2 그림자와 높이 [TDS]/[관찰]

- **그림자는 거의 쓰지 않아요.** 층(높이)은 딤, 회색 배경, 다크 모드의 표면 밝기로 표현해요.
- 그림자를 쓸 때도 아주 약하게 써요.

| 사용처 | 값 |
| --- | --- |
| 작은 버튼·컨트롤 | `0 1px 3px 0 rgba(0,0,0,0.09)` / `0 1px 2px 0 rgba(0,0,0,0.09)` |
| 토스트, 용어 설명 팝업 | `0 2px 30px 0 greyOpacity200` (넓고 흐린 그림자) |
| 입력 테두리 효과 | `inset 0 0 0 1px rgba(0,0,33,0.16)` |

### 5.3 구분선 [TDS]

| 종류 | 모양 | 용도 |
| --- | --- | --- |
| `full` | 1px 영역에 **0.5px** 선 | 영역 전체를 가로지르는 구분 |
| `padding24` | 같은 선, 왼쪽 24px 들여씀 | 목록 항목 사이 |
| `height16` | 16px 높이 `greyBackground` 띠 | 섹션 사이 큰 구분 |

> 목록 구분선은 실제로 **0.5px 두께**예요. 라이트 모드 `rgba(0,0,33,0.07)`, 다크 모드 `rgba(222,222,255,0.14)`로, `hairlineBorder`(`#E5E8EB`)보다도 훨씬 옅어요. [TDS]

> 테두리로 상자를 그리는 경우는 드물어요. 입력 칸도 테두리 대신 **회색 배경(`grey100`)** 이나 **밑줄**로 표현해요. [관찰]

## 6. 아이콘, 이모지, 그래픽

### 6.1 토스페이스 (Tossface) [공식]

토스가 직접 만든 **이모지 서체**예요.

- 작게 봐도 뜻이 명확하도록 **단순한 형태와 최소한의 묘사**를 목표로 해요. 기본 도형 위주로 만들었어요.
- 약 **3,600개** 이모지를 이미지가 아닌 **폰트**로 만들어서 모두 같은 균형과 볼륨감을 가져요.
- 소주, 김밥, 붕어빵처럼 **한국에 친숙한 사물**과 드론, 클라우드 같은 새로운 개념도 추가했어요.
- 오픈소스로 무료 공개했어요(GitHub `toss/tossface`, ttf·otf·woff·woff2·svg). 공개 이유는 "디자인 생태계를 나누는 것이 지키는 것보다 더 큰 가치를 가진다"는 **Universal Design** 관점이에요.
- **레드닷 어워드 2023** 브랜드&커뮤니케이션 부문 본상을 받았어요. 이모지 폰트로는 첫 수상이에요.
- **쓰는 방식** [관찰]: 목록 행의 왼쪽 아이콘, 빈 상태 일러스트, 알림 제목 앞, 이벤트 배너 등에서 **아이콘 대신** 친근한 시각 요소로 써요.

### 6.2 아이콘 [TDS]/[관찰]

- 아이콘 크기는 옆에 오는 글자 크기와 맞춰요. [TDS]
  - 기본 **24px**, 작은 곳(`t7` 이하) **20px**, 큰 제목 옆(`t1`) **31px**.
- 모양은 **둥근 끝과 둥근 모서리**, 단순한 형태예요. 단색 아이콘은 `grey400`~`grey600`, 강조할 때만 `blue500`을 써요.
- 목록 오른쪽 **꺾쇠(›) 화살표**는 `grey400` 정도로 약하게 둬요.
- 서비스 진입 아이콘(홈, 전체 메뉴)은 색이 들어간 **컬러 아이콘이나 입체(3D) 그래픽**을 써요. 기능 아이콘보다 친근하고 눈에 띄게 만들어요. [관찰]

### 6.3 그래픽과 일러스트 [관찰]

- **입체감 있는 3D 오브젝트**(동전, 지갑, 선물상자 등)로 혜택과 이벤트를 표현해요. 부드러운 조명과 파스텔 톤이 특징이에요.
- **Lottie 애니메이션**을 적극적으로 써요. 완료 체크, 로딩, 축하 연출 등이 있어요. TDS 완료 화면도 Lottie 기반 체크 애니메이션을 써요. [TDS]
- 은행·증권사·카드사는 **공식 로고를 원형 아이콘**으로 보여줘서 한눈에 알아보게 해요.

### 7.1 버튼 (Button) [TDS]

**크기**

| size | 높이 | 최소 너비 | 좌우 패딩 | 글자 | 모서리 |
| --- | --- | --- | --- | --- | --- |
| `xlarge` (기본값) | **56px** | 96px | 28px | 17px (`t5`) | 16px |
| `large` | **48px** | 80px | 16px | 17px (`t5`) | 14px |
| `medium` | **38px** | 64px | 16px | 15px (`t6`) | 10px |
| `small` | **32px** | 52px | 10px | 13px (`t7`) | 8px |

- 글자 굵기는 모두 **600(semibold)** 이에요.

**형태 (variant)**

| variant | 모양 |
| --- | --- |
| `fill` (기본) | 색이 꽉 찬 버튼. 주요 행동에 써요. |
| `weak` | 옅은 배경 + 진한 글자. 보조 행동에 써요. |

**색 (color)**: 라이트 모드 기준

| color | fill: 배경 / 글자 | weak: 배경 / 글자 | 쓰는 곳 |
| --- | --- | --- | --- |
| `primary` | `blue500` / 흰색 | `blue300` 15% / `blue600` | 기본 행동 |
| `danger` | `red500` / 흰색 | `red300` 15% / `red600` | 삭제, 해지 등 위험한 행동 |
| `dark` | `grey700` / 흰색 | `greyOpacity100` / `grey700` | 중립적인 보조 행동 |
| `light` | 흰색 / `blue700` | `whiteOpacity200` / 흰색 | 색 배경 또는 이미지 위 |

> 다크 모드의 weak 버튼은 배경 `blue600` 22%, 글자 `blue400`으로 바뀌어요. 브랜드 색을 바꿔 써도 OKLCH 명도를 계산해 **자동으로 대비가 맞는 조합**을 만들어요.

**배치 방식 (display)**

| display | 동작 |
| --- | --- |
| `inline` | 글자 길이만큼 |
| `block` | 부모 너비 100% |
| `full` | 너비 100% + **모서리 0** (화면 하단에 붙는 형태) |

**상태**

| 상태 | 표현 |
| --- | --- |
| 누름 | **0.96배로 축소**(`full`은 축소하지 않음) + 어두운 막을 겹침. 빠른 스프링(`rapid`) |
| 비활성 | fill은 **불투명도 0.3**, weak는 글자 불투명도 0.3 |
| 로딩 | 글자를 숨기고 점 3개 로더 표시. 배경이 0.6초 간격으로 은은하게 깜빡임. `aria-busy` 설정 |
| 색 전환 | `color`, `background-color` 등 **0.1초 ease-in-out** |

### 7.2 하단 고정 버튼 (BottomCTA / FixedBottomCTA) [TDS]/[관찰]

토스 화면에서 가장 상징적인 요소예요. **다음 행동은 항상 엄지가 닿는 화면 아래에** 있어요.

- 화면 하단 **고정**(`position: fixed`, `z-index: 50`)
- 여백: 좌우 **20px**, 아래 **20px** 또는 안전 영역(safe area) 중 큰 값
- 버튼 위에 높이 **36px**의 **배경색 → 투명 그라디언트**를 깔아서 스크롤되는 콘텐츠가 버튼 밑으로 자연스럽게 사라져요.
- 구성
  - **버튼 1개**: 전체 너비 주요 버튼 (예: "다음", "확인")
  - **버튼 2개**: 왼쪽 보조(weak) + 오른쪽 주요(fill), 간격 **8px**. 예: "닫기 | 확인"
- 키보드가 올라오면 **키보드 바로 위로 따라 올라가요.** 스크롤 중에는 잠시 반응을 늦춰 깜빡이지 않게 해요(400~700ms).

### 7.3 목록 행 (ListRow) [TDS]

토스 화면의 70%는 목록이라고 해도 될 만큼 가장 많이 쓰는 컴포넌트예요.

```
┌────────────────────────────────────────────┐
│ [●]  토스뱅크 통장                1,250,000원 › │
│      주 계좌                                    │
└────────────────────────────────────────────┘
 └24px┘                                  └16px┘
```

- **구조**: 왼쪽(아이콘, 로고, 아바타, 토스페이스) → 가운데(제목 + 부제) → 오른쪽(값, 뱃지, 스위치, 화살표)
- 여백: 왼쪽 **24px**, 오른쪽 **16px**, 위아래 **16px** 근처
- 항목 사이 구분선은 **왼쪽 24px 들여쓴 1px 선**
- **누름 효과**: 행 전체가 색이 바뀌는 게 아니라, 행 안쪽에 **위아래 4px·좌우 6px 떨어진 12px 둥근 사각형**이 `greyOpacity100`으로 살짝 나타나요. 버튼처럼 떠 있는 느낌을 줘요.
- 텍스트 줄 높이는 **1.35**(`line-height-s`)
- 제목은 `t5` `grey800`, 부제는 `t6`~`t7` `grey500`~`grey600` [관찰]

**함께 쓰는 목록 컴포넌트**

| 컴포넌트 | 역할 |
| --- | --- |
| `ListHeader` | 목록 위 섹션 제목과 설명 |
| `ListFooter` | 목록 아래 "더보기" 같은 텍스트 버튼 |
| `BoardRow` | 누르면 펼쳐지는 아코디언. 자주 묻는 질문 등 |
| `TableRow` | "이름 : 값" 형태의 정보 행. 거래 내역 상세, 영수증 등 |

### 7.4 입력 칸 (TextField) [TDS]

| variant | 글자 | 모양 | 쓰는 곳 [관찰] |
| --- | --- | --- | --- |
| `box` | 17px (`t5`) | 옅은 회색 상자(`greyOpacity50`, 1px `greyOpacity100` 테두리, 모서리 14px, 안쪽 14px 16px), 좌우 20px | 일반 정보 입력, 폼 |
| `line` | 22px (`t3`) | 밑줄형, 좌우 24px | 한 화면 한 질문 입력 |
| `big` | 30px (`t1`) | 밑줄형, 큰 글자 | 이름, 계좌번호 등 핵심 입력 |
| `hero` | 30px (`t1`) | 화면 주인공 | **금액 입력** |

- 커서 색 **`blue500`**, 입력 글자 `grey800`~`grey900`, 플레이스홀더 **`grey500`**
- 밑줄형(line·big)은 입력 글자 굵기 **600**, 밑줄 **2px** `grey100`이고, 포커스되면 `blue400`, 오류면 `red600`으로 바뀌어요.
- box형은 포커스되면 파란 막(`blue900` 5%), 오류면 빨간 막(`red900` 5%)이 살짝 덮여요.
- 라벨은 입력 칸 위(`t7`, 좌우 24px, 아래 6px), 도움말은 아래(`t7`, `grey600`)에 둬요. 포커스되면 라벨이 `blue600`, 오류면 라벨과 도움말이 `red600`으로 바뀌어요.
- `SplitTextField`: 주민등록번호 앞/뒤처럼 **나뉜 칸**
- `SearchField`: 검색 전용. 둥근 회색 배경
- `TextArea`: 여러 줄 입력

### 7.5 키패드 [TDS]/[관찰]

토스는 OS 키보드 대신 **자체 키패드**를 자주 써요.

- `NumberKeypad`: **금액 입력용**. 큰 숫자 버튼, `00` 또는 `000` 같은 빠른 입력, 지우기 버튼
- `FullSecureKeypad`: **비밀번호/PIN용 보안 키패드**. 한국 금융 앱의 보안 키패드처럼 입력 내용이 밖으로 새지 않게 만든 전용 키패드예요.
- `AlphabetKeypad`: 영문 입력
- 금액 입력 중에는 위에 "+1만 / +5만 / +10만 / 전액" 같은 **빠른 금액 칩**을 두는 경우가 많아요. [관찰]

### 7.6 바텀시트 (BottomSheet) [TDS]/[관찰]

**선택이나 짧은 확인**은 새 화면으로 넘기지 않고 바텀시트로 처리해요.

- 화면 끝에 붙지 않고 양옆을 **10px** 띄운 **떠 있는 카드**예요. 모서리는 **28px**이에요.
- 맨 위 16px 영역에 **손잡이(48×4px, 모서리 5px, `grey200`)** 가 있어요. 제목 영역은 위 21px, 아래 13px 여백이에요.
- 배경: `layeredBackground`, 뒤는 **딤 `rgba(0,0,0,0.2)`**(다크 모드 0.56)
- 딤을 눌러도 닫지 않게 설정한 시트는 좌우로 살짝 **흔들려서(wiggle)** 닫을 수 없다는 걸 알려줘요.
- 내용이 길면 스크롤 가장자리에 그라디언트가 생겨요.
- 구성: 제목(질문형) → 선택지 목록 또는 설명 → 하단 버튼
- 아래로 끌어내리거나 딤을 눌러 닫아요.

### 7.7 다이얼로그 (AlertDialog / ConfirmDialog) [TDS]/[공식]

- 화면 **정가운데**, 너비 `화면 - 64px`(최대 **320px**), 최대 높이 `화면 - 160px`
- 모서리 **24px**, 배경 `floatBackground`, 뒤는 딤(라이트 0.2, 다크 0.56)
- 구성: 제목(`t4` bold `grey800`) → 설명(`t6` medium `grey600`, 줄 높이 1.5) → 버튼
- 본문 여백은 위·좌우 **22px**, 제목과 설명 사이 **8px**
- 버튼 두 개는 여백 `20px 16px 16px` 안에 **반반** 나란히(간격 8px). 좁으면 위아래로 쌓이는데, 이때 주요 버튼이 위로 가요.
- 버튼 한 개짜리(AlertDialog)는 오른쪽 정렬된 텍스트 버튼이에요.
- 열릴 때 딤과 본문이 `quick` 스프링으로 나타나고, 닫힐 때 `rapid`로 사라져요.
  - `AlertDialog`: 버튼 1개 ("확인")
  - `ConfirmDialog`: 버튼 2개. **왼쪽은 항상 "닫기"** 로 통일해요. [공식] 오른쪽은 구체적인 행동("삭제하기", "해지하기")
- 다이얼로그는 **꼭 필요할 때만** 써요. 되돌릴 수 없는 행동, 중요한 경고에만 써요. [관찰]

### 7.8 토스트 (Toast) [TDS]

- 기본 **3초** 뒤 자동으로 사라져요.
- **흰색 알약** 모양이에요. 한 줄이면 모서리 **100px**, 여러 줄이면 **20px**이에요.
- 화면 **위쪽**에서 내려와 위에서 46px 지점에 멈춰요(`small` 스프링). 화면 아래에 뜨는 형태도 있어요.
- 안쪽 여백 **12px 16px**(왼쪽 아이콘이 있으면 왼쪽 12px), 아이콘 24px에 간격 8px
- 너비는 내용만큼, 최대 `min(375px, 화면 - 36px)`
- 그림자 `0 2px 30px greyOpacity200`
- 글자 `t6` semibold, 색 `greyOpacity800`. 다크 모드에서는 배경 `#3C3C47`, 글자 흰색
- 끌어서 치울 수 있고, 끄는 동안에는 타이머가 멈춰요.
- `PointToast`: 포인트·리워드 적립 알림 전용

### 7.9 상단 영역 (Top / TopNavigation) [TDS]/[관찰]

- `TopNavigation`: 왼쪽 **뒤로 가기**, 가운데 제목(대개 비워 둠), 오른쪽 아이콘·텍스트 버튼
- 페이지 제목은 내비게이션 바가 아니라 **본문 첫머리(`Top`)에 크게** 써요. 토스 화면의 가장 큰 특징이에요.
- `Top` 구성: upper(위 보조 요소) → subtitleTop → **title** → subtitleBottom → lower
- 스크롤하면 제목이 작아지면서 내비게이션 바 안으로 들어가는 방식도 써요.

### 7.10 선택 컨트롤 [TDS]/[관찰]

| 컴포넌트 | 특징 |
| --- | --- |
| `Checkbox` | 동그란 체크 모양이 흔해요. 카드형은 `grey100` 배경, 16px 둥근 사각형, 패딩 16px 20px |
| `Switch` | 50×30px 트랙(모서리 15px). 꺼지면 트랙 `grey200`에 16px 흰 동그라미, 켜지면 트랙 `blue500`에 **24px로 커진** 동그라미가 오른쪽으로 16px 이동해요. 누르면 0.96배로 줄어요 |
| `Tab` | 밑줄 또는 글자 굵기와 색으로 선택을 표시해요. 선택 `grey900`, 미선택 `grey500` |
| `SegmentedControl` | 회색 트랙 위에 흰 알약이 미끄러지는 형태 |
| `Chip` | 알약형. 필터와 빠른 선택에 써요. 왼쪽에 아이콘·이미지·카드, 오른쪽에 아이콘·숫자를 붙일 수 있어요 |
| `Selector` | 선택 상자를 누르면 바텀시트나 휠이 열려요 |
| `Stepper` / `NumericSpinner` | − / + 로 수량 조절 |
| `Slider` | 아래에 최소·중간·최대 라벨 (`t7` medium `grey600`) |

### 7.11 뱃지 (Badge) [TDS]

색은 6가지(blue, teal, green, red, yellow, elephant=회색)이고, 각각 채운형(fill)과 옅은형(weak)이 있어요. 글자는 **bold**예요.

| 색 | fill: 배경 / 글자 | weak: 배경 / 글자 (라이트) |

| blue | `blue500` / 흰색 | `rgba(49,130,246,0.16)` / `#1B64DA` |
| teal | `teal600` / 흰색 | `rgba(0,129,138,0.16)` / `#0C8585` |

- "NEW", "혜택", "D-3", "추천" 같은 짧은 라벨에만 써요.

### 7.12 피드백과 상태 [TDS]/[관찰]

### 7.13 약관 동의 (AgreementModule) [TDS]/[관찰]

금융 앱이라 약관 동의가 많아요. 토스는 이 과정을 최대한 가볍게 만들어요.

- **"전체 동의" 한 번**으로 끝낼 수 있게 맨 위에 둬요.
- 개별 약관은 접어 두고, 필요하면 펼쳐서 볼 수 있어요.
- 형태: 바텀시트형, 전체 화면형, 떠 있는 버튼형, 그라디언트 바텀시트형
- 목록 들여쓰기 단위 16px, 체크박스 24px, 왼쪽 24px [TDS]

### 7.14 차트 [TDS]/[관찰]

- `BarChart`, `DoughnutChart`: 소비 분석, 자산 구성 등
- 격자선과 축은 최소화하고 **핵심 숫자를 크게** 따로 보여줘요.
- 색은 카테고리 팔레트(blue, teal, purple, orange 등)를 쓰고, 강조 막대만 진하게 해요.

## 8. 인터랙션과 모션

### 8.1 모션 원칙 [관찰]

- **물리적이고 부드럽게**: 대부분 **스프링**으로 움직여요. 고정된 시간보다 자연스러운 감속이 중요해요.
- **즉각 반응**: 누르는 순간(`onPressStart`) 바로 반응해요. 손을 떼기 전부터 줄어들어요.
- **의미 있는 움직임만**: 상태 변화를 설명하는 데 모션을 써요. 장식용 모션은 절제해요.
- **완료는 축하하듯**: 송금 완료, 적립 같은 긍정적인 순간에는 체크 애니메이션, 폭죽, 동전 같은 연출을 넣어요.

### 8.2 스프링 토큰 [TDS]

| 토큰 | stiffness | damping | 느낌 / 용도 |
| --- | --- | --- | --- |
| `rapid` | 1000 | 55 | 가장 빠름. **버튼 누름** |
| `quick` | 800 | 55 | 빠른 상태 전환(로딩, 비활성, 복귀) |
| `small` | 480 | 50 | 작은 요소 이동 |
| `bounce` | 300 | 15 | 통통 튀는 강조 |
| `medium` | 270 | 25 | 일반 전환 |
| `basic` | 200 | 30 | 기본값. 나타나기 |
| `large` | 100 | 15 | 큰 요소 이동(시트, 패널) |
| `slow` | 70 | 20 | 느린 연출 |

(모든 토큰 mass = 1)

### 8.3 베지어 이징 토큰 [TDS]

| 토큰 | cubic-bezier | 비고 |
| --- | --- | --- |
| `linear` | `(0, 0, 1, 1)` | |
| `ease` | `(0.6, 0, 0, 0.6)` | 딤·그라디언트 페이드(0.4초) |
| **`out`** | **`(0.25, 0.1, 0.25, 1)`** | **기본값, 0.5초** |
| `expo` | `(0.16, 1, 0.3, 1)` | 빠르게 시작해 길게 감속 |
| `back` | `(0.34, 1.56, 0.64, 1)` | 살짝 넘쳤다 돌아옴 |

**자주 쓰는 수치**

| 인터랙션 | 값 |
| --- | --- |
| 버튼 누름 축소 | `scale(0.96)`, `rapid` 스프링 |
| 버튼 색 전환 | 0.1초 ease-in-out |
| 버튼 글자 다시 나타나기 | 0.1초 지연 후 페이드 |
| 로딩 깜빡임 | 0.6초, 반복 왕복, `out` |
| 토스트 유지 | 3초 |
| 토스트 등장 | 위에서 46px 지점까지 내려옴, `small` 스프링 |
| 바텀시트 딤을 눌렀을 때(닫기 금지) | 좌우 흔들림 2px → -2px → 1px → -1px → 0 |
| 스크롤 중 하단 버튼 반응 지연 | 400ms (키보드 위 고정일 때 700ms) |

### 8.4 토스다운 모션 연출 [관찰]/[공식]

- **숫자 롤링**: 금액·포인트가 바뀔 때 자릿수가 슬롯머신처럼 굴러가요. Simplicity 컨퍼런스 사이트에서도 숫자 롤링 컴포넌트와 스프링 토큰, 햅틱 헬퍼를 기반으로 인터랙션을 만들었다고 소개했어요. [공식]
- **햅틱**: 송금 완료, 스위치 전환, 당겨서 새로고침 같은 순간에 짧은 진동을 줘요.
- **화면 전환**: 다음 단계는 오른쪽에서 밀려 들어오고, 바텀시트는 아래에서 스프링으로 올라와요.
- **리스트 등장**: 항목이 조금씩 시차를 두고 아래에서 위로 페이드인해요(`FadeIn`, stagger).
- **완료 체크**: 원이 그려진 뒤 체크 표시가 그려지는 Lottie 애니메이션이에요.

### 8.5 제스처 [관찰]

- 바텀시트, 토스트: **아래로 끌어서 닫기**
- 목록: **당겨서 새로고침**
- 카드 캐러셀: 옆으로 넘기기, 다음 카드 일부를 보여줘서 더 있다는 걸 알려줘요.
- iOS: 왼쪽 가장자리에서 밀어서 뒤로 가기

## 9. UX 패턴과 화면 흐름

### 9.1 한 화면에 한 질문 (입력 흐름) [공식]/[관찰]

토스의 대표적인 입력 방식이에요. 긴 폼 하나 대신 **짧은 질문 여러 개**로 나눠요.

**송금 흐름 예시** [관찰]

| 단계 | 화면 제목 | 입력 방식 |
| --- | --- | --- |
| 1 | "누구에게 보낼까요?" | 최근 보낸 사람, 연락처, 계좌 목록 (**Easy to Answer**) |
| 2 | "얼마를 보낼까요?" | 큰 금액 입력(`hero`) + 숫자 키패드 + 빠른 금액 |
| 3 | "○○○님에게 50,000원을 보낼까요?" | 확인 화면. 받는 사람, 금액, 출금 계좌 요약 |
| 4 | "50,000원을 보냈어요" | 완료 애니메이션 + 요약 + "확인" |

**규칙**

- 제목은 **질문형**으로 써요("~할까요?", "~을 알려주세요").
- 화면에 들어오면 입력 칸에 **자동으로 포커스**하고 키보드를 바로 띄워요.
- 입력이 유효하면 하단 버튼이 **활성화**되고, 한 칸짜리 입력은 다 채우면 **자동으로 다음 단계**로 넘어가기도 해요.
- 앞에서 입력한 값은 다음 화면 제목이나 부제에 **다시 보여줘서** 맥락을 이어가요.
- 이미 아는 정보는 다시 묻지 않고 **미리 채워요**.

### 9.2 선택지를 줄이고 좋은 기본값 주기 [공식]/[관찰]

- 선택지가 많으면 **추천 하나**를 맨 위에 두거나 미리 선택해 둬요.
- 날짜, 은행, 기간 같은 선택은 **자유 입력보다 고르기**로 바꿔요(휠, 그리드, 칩).
- 드물게 쓰는 설정은 "더보기"나 별도 화면으로 숨겨요(**Minimum Features**).

### 9.3 가치 먼저, 비용은 나중에 [공식]

- 첫 화면에는 사용자가 **얻는 것**을 크게 보여줘요.
  - 예: "숨은 보험금 32만원을 찾았어요" → 그 다음에 본인인증
- 본인인증, 약관 동의, 개인정보 입력처럼 **귀찮은 일은 가치를 확인한 뒤에** 요청해요.
- 사용자는 첫 화면에서 얻을 이익과 치를 비용을 본능적으로 저울질하기 때문에, 가치를 먼저 보여주기만 해도 지표가 눈에 띄게 좋아졌다고 토스는 밝혔어요.

### 9.4 확인과 되돌리기 [관찰]

- 되돌릴 수 있는 행동은 확인 창 없이 바로 실행하고, 토스트로 **"되돌리기"** 를 줘요.
- 되돌릴 수 없는 행동(송금, 해지, 삭제)만 확인 화면이나 다이얼로그로 한 번 더 물어요.
- 송금 확인 화면에서는 **받는 사람 이름과 금액을 가장 크게** 보여줘서 실수를 막아요.

### 9.5 오류 처리 [공식]/[관찰]

- 오류는 **입력 칸 바로 아래**에 인라인으로 보여줘요. 가능한 한 전체 화면 오류는 피해요.
- 사용자를 탓하지 않고 **해결 방법**을 알려줘요.
  - 나쁜 예: "잘못된 계좌번호입니다."
  - 좋은 예: "계좌번호를 다시 확인해주세요"
- 시스템 오류일 때는 `Result` 화면으로 무슨 일이 생겼는지와 **다음에 할 수 있는 행동**("다시 시도하기")을 알려줘요.

### 9.6 완료 화면 [관찰]

- 가운데 **큰 체크 애니메이션**
- 제목: 무엇이 끝났는지 **과거형 해요체**("보냈어요", "신청했어요")
- 핵심 정보 요약(금액, 받는 사람, 예상 도착 시간)
- 버튼: "확인" 하나. 필요하면 다음 행동을 하나 더 제안해요("친구에게 알리기").

### 9.7 금융 앱 특화 패턴 [관찰]

| 패턴 | 설명 |
| --- | --- |
| 금액 먼저 | 자산, 잔액, 결제 금액이 화면의 주인공이에요. 가장 크고 굵게 보여줘요. |
| 잔액 숨기기 | 한 번 눌러 금액을 가릴 수 있어요(공공장소 대비). |
| 보안 키패드 | 비밀번호는 배열이 바뀌는 자체 키패드로 입력해요. |
| 간편 인증 | PIN, 생체인증으로 공인인증서 없이 인증해요. |
| 상승·하락 색 | 빨강(상승) / 파랑(하락) + 부호 |
| 홈 = 내 자산 한눈에 | 계좌, 카드, 대출, 투자를 **목록**으로 모아 보여주고, 누르면 상세로 들어가요. |
| 혜택 탭 | 만보기, 퀴즈, 이벤트 등 가벼운 리워드 경험을 모아 둬요. 3D 그래픽과 토스페이스로 친근하게 꾸며요. |

## 10. UX 라이팅: 보이스와 톤

토스의 목소리는 **친절하고 믿을 수 있는 친구**예요. 은행원처럼 딱딱하지도, 광고처럼 과장되지도 않아요.

### 10.1 5가지 코어 밸류 [공식]

| 가치 | 뜻 |
| --- | --- |
| **Clear** (명확한) | 누가 읽어도 한 번에 이해돼요. |
| **Concise** (간결한) | 필요한 말만 해요. |
| **Casual** (친근한) | 딱딱한 금융 용어 대신 일상 언어를 써요. 토스 보이스를 다른 서비스와 구분하는 결정적인 요소예요. |
| **Respect** (존중하는) | 사용자를 가르치거나 몰아붙이지 않아요. |
| **Emotional** (공감하는) | 정보 전달을 넘어 사용자의 감정을 헤아려요. |

### 10.2 8가지 라이팅 원칙 [공식]

문구를 다 쓴 뒤 스스로 점검하는 질문이에요.

| # | 원칙 | 점검 질문 |
| --- | --- | --- |
| 1 | **Predictable hint** | 다음 화면을 예상할 수 있는 힌트가 있는가? |
| 2 | **Weed cutting** | 의미 없는 **단어**를 모두 뺐는가? |
| 3 | **Remove empty sentences** | 의미 없는 **문장**을 모두 뺐는가? |
| 4 | **Focus on key message** | 정말 중요한 메시지만 전하고 있는가? |
| 5 | **Easy to speak** | 이해하기 어려운 용어나 표현을 쓰지 않았는가? |
| 6 | **Suggest than force** | 특정 행동을 강요하거나 겁을 주고 있지 않은가? |
| 7 | **Universal words** | 모두가 이해할 수 있고, 누구에게도 해가 되지 않는 말인가? |
| 8 | **Find hidden emotion** | 정보 전달을 넘어 사용자의 감정에 공감했는가? |

### 10.3 문장 규칙 [공식]

앱인토스 개발자센터에서 공개한 토스 보이스 규칙이에요.

1. **모든 문구는 해요체**로 써요. 상황과 맥락에 상관없이 통일해요. 경어(~하시겠습니까, ~드립니다)는 아주 제한적으로만 써요.
2. **능동형 문장**을 써요. 수동형은 꼭 필요할 때만 써요.
3. **긍정형 문장**을 써요. "안 돼요", "없어요" 대신 "~하면 할 수 있어요"처럼 방법을 알려줘요.
4. **다이얼로그 왼쪽 버튼은 "닫기"** 로 통일해요.

### 10.4 고쳐 쓰기 예시

> 아래 예시는 위 원칙을 적용해 이 문서에서 만든 예시예요. 토스 앱의 실제 문구와 다를 수 있어요.

| 원칙 | 이전 | 이후 |
| --- | --- | --- |
| 해요체 | 송금이 완료되었습니다. | 송금을 완료했어요 / 50,000원을 보냈어요 |
| 과한 경어 빼기 | 비밀번호를 입력하여 주시기 바랍니다. | 비밀번호를 입력해주세요 |
| 능동형 | 신청이 접수되었습니다. | 신청을 받았어요 |
| 긍정형 | 영업일이 아니면 이체할 수 없습니다. | 영업일에 다시 이체할 수 있어요 |
| 쉬운 말 | 가상계좌 발급 후 입금 기한 내 미입금 시 자동 취소됩니다. | 내일 밤 12시까지 입금하지 않으면 자동으로 취소돼요 |
| 잡초 뽑기 | 고객님의 소중한 개인정보를 안전하게 보호하기 위해 본인인증을 진행해주세요. | 본인인증이 필요해요 |
| 강요하지 않기 | 지금 가입하지 않으면 혜택이 사라집니다! | 지금 가입하면 혜택을 받을 수 있어요 |
| 다음 화면 힌트 | 다음 | 인증하고 계속하기 |
| 핵심만 | 계좌 등록이 정상적으로 처리되어 이제부터 해당 계좌로 송금 및 출금이 가능합니다. | 계좌를 연결했어요 |

### 10.5 요소별 쓰는 법 [관찰]

| 요소 | 규칙 | 예 |
| --- | --- | --- |
| 화면 제목 | 질문형 또는 결과형, 한 줄~두 줄 | "어떤 계좌로 받을까요?", "대출 한도를 확인했어요" |
| 부제 | 제목을 보충하는 한 문장, `grey600` | "언제든 바꿀 수 있어요" |
| 주요 버튼 | 짧은 동사형, 2~6글자 | "다음", "확인", "보내기", "시작하기" |
| 결과가 중요한 버튼 | 무엇을 하는지 구체적으로 | "50,000원 보내기", "해지하기" |
| 다이얼로그 | 제목은 질문, 버튼은 "닫기 / 구체적 행동" | "카드를 해지할까요?" → [닫기] [해지하기] |
| 토스트 | 결과를 짧게, 과거형 | "계좌번호를 복사했어요" |
| 빈 상태 | 상황 + 다음 행동 | "아직 거래 내역이 없어요" |
| 오류 | 탓하지 않기 + 해결 방법 | "인터넷 연결을 확인해주세요" |
| 숫자 | 세 자리 쉼표, 단위 붙여 쓰기 | "1,250,000원", "연 3.5%" |

### 10.6 용어를 바꾸는 방식 [공식]/[관찰]

금융·IT 용어는 **사용자가 실제로 겪는 결과**로 바꿔 말해요(**Casual Concept**).

| 딱딱한 말 | 토스식 표현의 방향 |
| --- | --- |
| 이체 | 보내기 / 송금 |
| 입금 | 받기 / 들어왔어요 |
| 원리금균등상환 | 매달 같은 금액 갚기 |
| 만기일시상환 | 끝날 때 한 번에 갚기 |
| 인증서 로그인 | 간편하게 로그인하기 |
| 오류가 발생하였습니다 | 잠시 문제가 생겼어요 |

## 11. 접근성

[TDS]로 확인한 것과 [관찰]한 것을 함께 적었어요.

- **글자 크기 확대**: OS 설정(iOS 최대 310%, Android)을 따라가되 토큰별 최대값을 둬서 화면이 깨지지 않게 해요. ([3.6](#36-글자-크기-확대-대응-dynamic-type-tds) 참고) [TDS]
- **터치 영역**: 주요 버튼 56px·48px, 목록 행 전체가 누르는 영역이에요. 작은 버튼도 최소 32px이에요. [TDS]
- **보조기기 알림**: 로딩 중인 버튼은 `aria-busy`, `aria-live="polite"`, 인증 성공은 `aria-live="assertive"`로 스크린리더에 알려요. [TDS]
- **색만으로 구분하지 않기**: 상승·하락에는 +/− 부호, 오류에는 문구를 함께 써요. [관찰]
- **대비**: 본문은 `grey700` 이상, 캡션도 `grey500`(`#8B95A1`)보다 흐리게 쓰지 않아요. [관찰]
- **쉬운 말 자체가 접근성**: 어려운 금융 용어를 풀어 쓰는 것은 고령층과 금융 초보자를 위한 접근성이기도 해요. [관찰]

## 12. 다크 모드

[TDS] 값을 바탕으로 정리했어요.

| 원칙 | 내용 |
| --- | --- |
| 단순 반전이 아니에요 | 모든 색을 다크 모드용으로 **따로 조정**했어요. 예: `blue500` `#3182F6` → `#3485FA`, `red500` `#F04452` → `#F04251` |
| 스케일을 뒤집어요 | 50~900 순서가 뒤집혀서 **900이 가장 밝아요.** 토큰 이름을 그대로 두어도 "숫자가 클수록 대비가 크다"가 유지돼요. |
| 배경은 순수 검정이 아니에요 | 기본 배경 `#17171C`(약간 보랏빛이 도는 짙은 회색), 회색 배경은 더 어두운 `#101013` |
| 높이는 밝기로 표현해요 | 기본 `#17171C` → 한 단계 위 `#202027` → 떠 있는 면 `#2C2C35` |
| 딤을 더 진하게 | 모달 뒤 딤 `0.2` → `0.56` |
| 투명 그레이를 바꿔요 | 남색 기반 `greyOpacity` → 흰색(연보라 기운) 기반 `whiteOpacity` |
| 버튼 weak 색 | 배경 `blue600` 22%, 글자 `blue400`으로 더 밝게 |

## 13. 적용 체크리스트

토스 스타일로 화면을 만들었다면 이렇게 점검해 보세요.

**구조**

- [ ] 이 화면이 전달하는 메시지가 **하나**인가?
- [ ] 사용자가 **3초 안에** 답할 수 있는 질문인가?
- [ ] 이미 아는 정보를 다시 묻고 있지 않은가?
- [ ] 가치(혜택)를 비용(입력, 인증)보다 **먼저** 보여줬는가?
- [ ] 이 기능이나 옵션이 정말 없으면 안 되는가?

**시각**

- [ ] 배경은 흰색, 강조색은 `blue500` **하나**만 썼는가?
- [ ] 제목은 본문 첫머리에 크게(`t2`~`t3`, bold, `grey900`) 썼는가?
- [ ] 화면 좌우 여백이 24px(하단 버튼은 20px)인가?
- [ ] 주요 행동이 **하단 고정 56px 버튼**에 있는가?
- [ ] 테두리와 그림자 대신 여백, 회색 배경, 들여쓴 구분선으로 나눴는가?
- [ ] 모서리를 요소 크기에 맞게 충분히 둥글렸는가?
- [ ] 금액은 쉼표와 단위를 붙여 가장 크게 보여줬는가?

**인터랙션**

- [ ] 버튼을 누르면 즉시 0.96배로 줄어드는가?
- [ ] 움직임이 스프링처럼 자연스럽게 감속하는가?
- [ ] 되돌릴 수 있는 행동에 확인 창을 남발하지 않았는가?
- [ ] 로딩은 스켈레톤으로, 완료는 체크 애니메이션으로 보여주는가?

**문구**

- [ ] 모든 문장이 해요체인가?
- [ ] 능동형, 긍정형으로 썼는가?
- [ ] 전문 용어를 쉬운 말로 바꿨는가?
- [ ] 버튼 문구가 짧고, 누르면 무슨 일이 생기는지 알 수 있는가?
- [ ] 다이얼로그 왼쪽 버튼이 "닫기"인가?

**접근성**

- [ ] 글자 크기를 키워도 레이아웃이 깨지지 않는가?
- [ ] 색 말고도 부호나 문구로 의미를 전달하는가?
